# 制衣厂ERP系统 - 完整需求文档

## 概述

本系统是一套面向制衣厂的生产管理系统，核心功能包括：基础数据管理、订单与配料、裁床与开菲、移动端扫码报工、管理员后台、财务模块和权限管理。采用微信小程序作为移动端平台，Web端用于管理后台。

### 核心设计理念
- 以「扎」为生产流转基本单位，每扎附带菲仔标签（含裁床条形码+扎号QR码）
- 工人通过手机扫码报工，系统自动计算计件工资
- 支持管理员对误扫/漏扫进行纠正，QR码自动失效与复活
- 按订单维度管理工序定价和物料清单，支持灵活配置

---

# 模块1：基础配置

## 概述

基础配置模块是整个ERP系统的地基，用于管理全厂通用的基础数据。包括员工、工序、款号、客户、供应商等核心主数据。

---

## 1.1 员工档案管理

### 功能说明
管理全厂员工的基本信息，生成专属登录码供工人免密登录扫码报工。

### 页面布局
- **列表页**：员工列表 + 搜索栏 + 新增按钮
- **弹窗**：新增/编辑员工信息

### 列表页字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 工号 | 文本 | 系统自动生成，格式如 A001、A002... |
| 姓名 | 文本 | |
| 手机号 | 文本 | 用于联系 |
| 角色 | 标签 | 从权限管理中选择的角色名称 |
| 账号状态 | 标签 | 启用（绿色）/ 停用（灰色） |
| 登录码 | 文本+操作 | 展示登录码，支持「查看」和「重置」 |
| 登录账号 | 文本 | Web端登录账号，默认等于工号 |
| 操作 | 按钮 | 编辑、停用/启用、重置登录码、重置密码 |

### 新增/编辑弹窗字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 工号 | 文本 | 系统生成 | 自动递增，如 A001、A002 |
| 姓名 | 文本 | 是 | |
| 手机号 | 文本 | 否 | |
| 角色 | 下拉选择 | 是 | 从「权限管理-角色管理」中选择，决定可使用的功能和可访问的平台 |
| 登录账号 | 文本 | 否 | 用于Web端登录，默认等于工号，可修改 |
| 登录密码 | 文本 | 否 | 用于Web端登录，管理员设置初始密码 |
| 登录码 | 文本 | 系统生成 | 用于移动端登录 |
| 备注 | 文本 | 否 | |

### 操作功能

| 功能 | 说明 |
|------|------|
| 新增员工 | 打开弹窗填写信息，工号自动生成 |
| 编辑 | 修改员工信息 |
| 停用/启用 | 停用后该员工无法扫码报工，历史数据保留 |
| 生成登录码 | 新增员工时自动生成专属登录码（一串字符或二维码） |
| 重置登录码 | 重置后旧登录码失效，需重新打印给工人 |
| 搜索 | 按工号、姓名模糊搜索 |

### 业务规则
- 工号由系统自动生成，格式为字母+三位数字（A001、A002...）
- 每个员工有唯一登录码，用于移动端（微信小程序）登录
- 登录账号默认等于工号，可手动修改，用于Web管理后台登录
- 登录密码由管理员设置初始密码，员工可自行修改
- 停用员工不影响已有报工记录和工资数据
- 角色决定了员工可以访问哪些平台（Web端/移动端）和功能

# 模块2：订单与配料

## 概述

订单与配料模块是业务核心，负责管理客户订单、工序定价、物料清单和出货。采用「一单一款」的结构，每个订单对应一个款号，款号下按颜色×尺码矩阵管理数量。

---

## 数据结构总览

```
订单（订单号、客户、款号、订单金额、状态）
  ├── 颜色尺码明细（颜色、尺码、数量）
  ├── 工序定价（该订单的工序列表+工价，从款号标准模板带出，可修改）
  ├── 物料清单（该订单的物料列表，从款号标准模板带出，可修改）
  └── 出货记录
```

---

## 2.1 订单创建与管理

### 页面布局
- **列表页**：订单列表 + 搜索栏 + 新增按钮

### 颜色尺码矩阵

选择款号后，支持以「颜色×尺码」矩阵形式录入数量：
- 行 = 颜色（可多行，手动输入）
- 列 = 尺码（可多列，手动输入）
- 格子 = 数量
- 总件数自动汇总矩阵中所有格子的数量

### 订单详情页布局

- **Tab1：颜色尺码明细** - 展示颜色×尺码矩阵，可编辑数量
- **Tab2：工序定价** - 该订单的工序列表和工价
- **Tab3：物料清单** - 该订单的物料列表
- **Tab4：出货记录** - 出货记录列表和进度

### 订单状态管理

#### 状态定义

| 状态 | 标签颜色 | 说明 |
|------|---------|------|
| 待确认 | 灰色 | 订单刚创建，默认状态 |
| 已确认 | 蓝色 | 管理员手动点击「确认订单」 |
| 生产中 | 橙色 | 裁床开菲后自动变更 |
| 部分出货 | 黄色 | 有出货记录但未出齐 |
| 已完工 | 紫色 | 所有扎号全部工序完成（系统自动检测） |
| 已出货 | 绿色 | 出货数量 ≥ 订单总件数 |
| 已结算 | 深灰 | 管理员手动点击「标记结算」 |

#### 状态流转规则

| 当前状态 | 可流转到 | 触发方式 |
|---------|---------|---------|
| 待确认 | 已确认 | 管理员手动确认 |
| 已确认 | 生产中 | 裁床开菲后自动变更 |
| 生产中 | 部分出货 | 有出货记录 |
| 生产中 | 已完工 | 系统自动检测所有扎号完成 |
| 部分出货 | 已完工 | 系统自动检测所有扎号完成 |
| 部分出货 | 已出货 | 出货数量 ≥ 订单总件数 |
| 已完工 | 已出货 | 出货数量 ≥ 订单总件数 |
| 已出货 | 已结算 | 管理员手动标记 |

#### 自动状态判断

| 条件 | 自动变更状态 |
|------|------------|
| 出货数量 > 0 且 < 订单总件数 | 订单状态 → 部分出货 |
| 出货数量 ≥ 订单总件数 | 订单状态 → 已出货 |
| 所有扎号全部工序完成 | 订单状态 → 已完工 |

### 业务规则
- 订单号由系统自动生成，唯一不可修改
- 确认订单后才能进行裁床开菲操作
- 已删除的订单不可恢复，关联的扎号、报工记录等一并逻辑删除
- 订单金额为手动输入的整单金额，不自动计算

# 模块3：裁床与开菲

## 概述

裁床与开菲模块负责将订单拆分为扎号，生成并打印菲仔二维码，管理扎号的生产状态。裁剪作为第一道工序，裁床师傅通过扫裁床条形码完成裁剪报工。

---

## 3.1 裁床计划

### 功能说明
管理每个订单的裁床计划。在实际服装生产中，一床次裁剪（拉布铺料）通常会使用一张包含多个尺码的排料图。因此，**一个裁床计划代表物理上的一床次裁剪**，支持单床内包含**多颜色、多尺码的配比组合**。

### 页面布局
- **列表页**：裁床计划列表（展示物理床次信息及配比预览） + 筛选栏 + 新增按钮
- **弹窗**：新增/编辑裁床计划（支持多色多码矩阵及排料配比录入）

### 筛选条件

| 筛选项 | 说明 |
|--------|------|
| 订单号 | 搜索/下拉选择 |
| 款号 | 搜索/下拉选择 |
| 状态 | 待裁剪 / 已裁剪 / 已开菲 / 已报工 |

### 列表页字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 订单号 | 文本 | 关联的订单 |
| 款号 | 文本 | 从订单带出 |
| 床次 | 数字 | 第1床、第2床... |
| 铺料层数 | 数字 | 该床物理拉布层数 |
| 裁剪面料 | 文本 | 裁剪的面料名称 |
| 裁剪部位 | 文本 | 裁剪的衣服部位（如整套、领子等） |
| 配比预览 | 文本 | 如：红色(S/1, M/2, L/1) |
| 总计划数 | 数字 | 各色码（层数×配比）之和 |
| 总实际数 | 数字 | 裁完录入的实际件数之和 |
| 每扎件数 | 数字 | 本床分扎规则，如 20 |
| 总扎数 | 数字 | 系统自动计算的该床总扎数 |
| 裁床条形码 | 文本+操作 | 展示条码 ID（如 `CUT202606050001`），支持「打印」 |
| 裁床日期 | 日期 | |
| 状态 | 标签 | 待裁剪 / 已裁剪 / 已开菲 / 已报工 |
| 操作 | 按钮 | 编辑、删除、录入实际数、开菲、打印裁床码 |

### 新增/编辑裁床计划弹窗字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 订单号 | 下拉选择 | 是 | 选择关联订单，自动带出款号及可选的颜色尺码列表，并自动加载该订单的配料表面料 |
| 裁剪面料 | 下拉选择 | 是 | 关联并选择该订单配料表中的面料/原料（如：主面料、里料等） |
| 裁剪部位 | 输入选择框 | 否 | 下拉选择预设部位，并支持自由手输。当选定订单号和裁剪面料后，系统自动读取并填充该面料在该订单物料清单中配置的【默认裁剪部位】。 |
| 床次 | 数字 | 是 | 该订单的床次，自动递增建议（如 1、2、3），可修改 |
| 铺料层数 | 数字 | 是 | 本床实际铺料层数，如 50 |
| 配比矩阵录入 | 表格/矩阵 | 是 | 选择颜色、尺码，录入排料配比（如：红色 M码 配比为 2，L码 配比为 1） |
| 明细预览 | 表格 | 否 | 自动计算：计划数 = 层数 × 配比。显示每种颜色尺码的计划件数，且不可超过订单剩余可裁数 |
| 每扎件数 | 数字 | 是 | 本床的分扎规则，如 20 件/扎 |
| 裁床日期 | 日期 | 否 | 默认今天 |

### 操作功能

| 功能 | 说明 |
|------|------|
| 新增 | 创建裁床计划，系统自动生成唯一裁床条形码 ID（格式如 `CUT202606050001`） |
| 编辑 | 修改计划信息（包含配比及层数） |
| 删除 | 删除裁床计划 |
| 录入实际数 | 录入各颜色尺码的实际产出件数（默认带出计划数供微调） |
| 开菲 | 录入实际数后执行开菲，系统按颜色尺码明细自动分扎，生成唯一的扎号 ID（格式如 `BUN2026060500001`） |
| 打印裁床码 | 单独打印裁床条形码（开菲前即可打印） |

### 业务规则
- 每床的每扎件数单独设置，不使用全局默认值。
- 同一床次下，不同颜色、不同尺码在分扎时**各自独立分扎**（同色同码一扎）。
- 尾扎不足一扎时，单独成扎（如某色码实际数 95 件，每扎 20 件 → 5扎，最后一扎 15 件）。
- 创建裁床计划时系统自动生成唯一裁床码 ID，可立即打印。
- 开菲后状态变为「已开菲」，扎号生成，可打印菲仔。
- 已开菲的裁床计划不可删除。

## 3.2 订单条码

### 功能说明
每个订单生成一个唯一的订单条码，用于裁床报工和其他无扎号码的工序报工。所有菲仔共享相同的订单条码。

### 订单条码内容
条形码内不编码 JSON 字符串，仅编码一个极简的全局唯一 ID 字符串：

**格式**：`ORD` + 年月日(8位) + 顺序流水号(4位)
**示例**：`ORD202606050001`

后台通过该 ID 关联订单，获取对应的款号、各颜色尺码及实际产出数据。

### 使用场景

| 场景 | 说明 |
|------|------|
| 裁床报工 | 裁床师傅扫码完成整单裁剪工序 |
| 按单工序报工 | 包装、整件熨烫、出货检验等无扎号码的工序 |

### 打印方式
- 创建订单后即可打印订单条码。
- 与菲仔一起打印：每个菲仔标签上同时包含订单条形码和扎号QR码。
- 也可单独打印订单条码，张贴在工位或订单文件上。

### 裁床师傅报工流程
1. 裁床师傅按照排料图裁完布料。
2. 管理员录入各色码的实际件数并执行开菲。
3. 打印菲仔（菲仔上包含订单条形码和扎号QR码）。
4. 裁床师傅扫任意一张菲仔上的订单条形码。
5. 系统识别当前登录用户，选择「裁剪」工序，自动为该订单下的**所有颜色、所有尺码、所有扎号**完成裁剪。
6. 裁剪计件工资自动计算：该订单总实际件数 × 裁剪工价。

### 按单工序报工流程
1. 工人扫订单条码。
2. 系统显示该订单可报工的工序列表（裁剪、包装、整件熨烫等）。
3. 工人选择完成的工序。
4. 系统记录报工信息。

### 业务规则
- 工人通过登录状态自动识别（扫码时必须已登录）。
- 订单条码在开菲后才能用于裁床报工（开菲前扫码提示「请先开菲」）。
- 扫订单条码后，可选择「裁剪」工序完成整单裁剪，或选择其他按单工序。
- 同一订单的同一工序不可重复扫码报工（提示「该工序已报工」）。

|------|------|-----------------|------------------|

| 红色 | M | 100 | 102 |
| 红色 | L | 50 | 49 |

## 3.4 自动分扎

### 功能说明
执行开菲时，系统根据各颜色尺码的实际件数 and 每扎件数自动拆分扎号。

### 扎号格式

**格式**：`床次-序号`
**分扎原则**：按每个颜色、尺码分别独立进行分扎。

**示例**：第 1 床裁剪了红色 S 码 51 件，红色 M 码 102 件，每扎 20 件。
- **红色 S 码** 分扎结果：
  | 扎号 | 颜色 | 尺码 | 件数 |
  |------|------|------|------|
  | 1-001 | 红色 | S | 20件 |
  | 1-002 | 红色 | S | 20件 |
  | 1-003 | 红色 | S | 11件 |
- **红色 M 码** 分扎结果：
  | 扎号 | 颜色 | 尺码 | 件数 |
  |------|------|------|------|
  | 1-004 | 红色 | M | 20件 |
  | 1-005 | 红色 | M | 20件 |
  | 1-006 | 红色 | M | 20件 |
  | 1-007 | 红色 | M | 20件 |
  | 1-008 | 红色 | M | 20件 |
  | 1-009 | 红色 | M | 2件 |

### 全局唯一标识
系统内部使用 `订单号-床次-序号` 作为扎号的物理唯一标识。另外，系统会为每扎生成一个极简的全局唯一 ID 存入二维码（如 `BUN2026060500001`）。

### 分扎逻辑
对该床下的每个颜色-尺码明细分别计算：
```
该组总扎数 = 向上取整(实际件数 / 每扎件数)
前N-1扎 = 每扎件数
最后一扎 = 实际件数 - (总扎数-1) × 每扎件数
```

### 业务规则
- 开菲后自动生成扎号，扎号不可手动修改。
- 尾扎单独一扎，即使只有 1 件。
- 开菲后自动变更订单状态为「生产中」。

---

## 3.5 菲仔打印

### 功能说明
分扎完成后，生成并打印菲仔标签。每个菲仔标签包含两个码：订单条形码（同一订单相同）和扎号QR码（每扎唯一）。

### 菲仔标签内容

| 信息 | 说明 |
|------|------|
| 订单号 | 文本展示 |
| 款号 | 文本展示 |
| 颜色 | 文本展示 |
| 尺码 | 文本展示 |
| 扎号 | 文本展示，如 1-001 |
| 件数 | 文本展示，如 20件 |
| 面料 | 文本展示，如 主面料 |
| 部位 | 文本展示，如 袖子 |
| 订单条形码 | 1D 条形码，编码内容为极简全局唯一 ID（如 `ORD202606050001`） |
| 扎号QR码 | 2D 二维码，编码内容为极简全局唯一 ID（如 `BUN2026060500045`） |

### 菲仔标签布局示例

```
┌─────────────────────────────────┐
│ 订单号：ORD20240101001           │
│ 款号：SP-001      颜色：红色      │
│ 尺码：M          扎号：1-001      │
│ 件数：20件        面料：主面料    │
│ 部位：袖子                       │
│                                 │
│ ┌──────────┐   ┌──────────┐    │
│ │ ||||||||||│   │ ┌──────┐ │    │
│ │ 订单条形码  │   │ │ QR码  │ │    │
│ │ (128格式) │   │ └──────┘ │    │
│ └──────────┘   └──────────┘    │
│  ↑ 裁床/按单工序扫    ↑ 按扎工序扫  │
└─────────────────────────────────┘
```

> [!IMPORTANT]
> 菲仔标签虽采用极简 ID 进行扫码，但打印在标签面上的文本信息（如订单号、颜色、尺码、件数、面料、部位等）必须清晰完整，便于工人肉眼核对。

### 扎号QR码内容
二维码中不再编码 JSON 字符串，仅编码一个极简的全局唯一 ID 字符串：

**格式**：`BUN` + 年月日(8位) + 顺序流水号(5位)
**示例**：`BUN2026060500045`

后台通过该 ID 关联具体的扎号明细并获取其状态。

### 打印功能

| 功能 | 说明 |
|------|------|
| 单扎打印 | 选择某一个扎，打印单张菲仔 |
| 批量打印 | 选择当前床次或当前订单，批量打印所有扎仔（打印顺序按扎号严格递增） |
| 重新打印 | 某扎菲仔丢失或损坏时，重新打印（不影响扎号和生产数据） |
| 打印订单码 | 单独打印订单条形码 |

### 打印配置

| 配置项 | 说明 |
|--------|------|
| 打印机类型 | 条码打印机（热敏打印机） |
| 标签尺寸 | 支持自定义，默认 60mm×40mm |
| 打印模板 | 菲仔标签的布局模板 |

### 业务规则
- 菲仔打印不限次数，重打不影响任何数据。
- 每个菲仔包含两个码：订单条形码（同一订单相同）和扎号QR码（每扎唯一）。
- 打印时自动调用本地条码打印机驱动。
- 创建订单后即可打印订单码，开菲后可打印完整菲仔（含两个码）。

- 管理员清除误扫记录后，该扎状态变回「生产中」，QR码自动复活
- 扎号详情页可查看完整的报工历史和操作记录

# 模块4：移动端

## 概述

移动端以微信小程序为载体，支持员工端和管理员端两种角色。登录后根据角色展示不同的功能菜单。采用免密登录方式，降低使用门槛。

---

## 4.1 登录

### 功能说明
移动端支持两种登录方式：员工登录（工号）和管理员登录（账号+密码），通过Tab切换。

### 登录页面设计

页面顶部有两个切换Tab：「员工登录」和「管理员登录」

#### 员工登录模式

| 元素 | 说明 |
|------|------|
| 工号输入框 | 输入工号，如 A001 |
| 登录按钮 | 点击验证并登录 |

**登录流程**：
1. 输入工号
2. 系统验证工号是否存在且状态为启用
3. 检查该员工角色是否有移动端权限
4. 验证通过，进入员工端主页

#### 管理员登录模式

| 元素 | 说明 |
|------|------|
| 账号输入框 | 输入登录账号 |
| 密码输入框 | 输入登录密码 |
| 登录按钮 | 点击验证并登录 |

**登录流程**：
1. 输入账号和密码
2. 系统验证账号密码是否正确且状态为启用
3. 检查该员工角色是否有移动端权限
4. 验证通过，进入管理员端主页

### 错误提示

| 情况 | 提示信息 |
|------|---------|
| 工号/账号不存在 | 「账号不存在」 |
| 密码错误 | 「密码错误」 |
| 账号已停用 | 「账号已停用，请联系管理员」 |
| 角色无移动端权限 | 「无权限，请联系管理员」 |

### 功能菜单加载

登录后，系统根据员工关联的角色（在「权限管理-角色管理」中配置）加载对应的功能菜单。

| 角色示例 | 可见功能 |
|---------|---------|
| 报工角色 | 扫码报工、我的工资、报工记录 |
| 裁床角色 | 裁床管理、扫码报工、我的工资、报工记录 |
| 组长角色 | 生产看板、异常预警、扎号查询、订单查询、计时录入 |
| 超级管理员 | 全部功能 |

### 业务规则
- 员工登录：输入工号即可登录，无需密码
- 管理员登录：输入账号+密码登录
- 登录账号和密码在「基础配置-员工档案」中设置
- 停用状态的员工无法登录
- 登录态长期有效（Token不过期或长期有效）
- 同一账号可在多台设备登录（不踢出其他设备）

## 5.2 进度断层预警

### 功能说明
集成在看板页面中，自动检测「前置工序未完成，后置工序已扫」的情况。仅作为提示，管理员自行判断是异常还是正常并行操作。

### 预警规则
按照订单中工序的排列顺序，如果第N道工序已完成，但第N-1道工序未完成，则标记为断层预警。

### 预警列表

| 字段 | 类型 | 说明 |
|------|------|------|
| 扎号 | 文本 | 如：1-001 |
| 订单号 | 文本 | |

| 前置工序 | 文本 | 未完成的工序 |
| 后置工序 | 文本 | 已完成的工序 |
| 报工人 | 文本 | 后置工序的报工人 |
| 报工时间 | 日期时间 | |
| 状态 | 标签 | 待处理 / 已忽略 / 已清除 / 已补录 |
| 操作 | 按钮 | 忽略、清除后置、补录前置 |

### 管理员操作

| 操作 | 说明 | 系统行为 |
|------|------|---------|
| 忽略 | 确认是正常并行操作 | 记录处理结果，关闭预警 |
| 清除后置工序 | 认为是误扫 | 跳转到清除页面，清除该报工记录 |
| 补录前置工序 | 前置工序漏扫 | 跳转到补录页面，为漏扫的前置工序补录 |

### 处理记录

| 字段 | 说明 |
|------|------|

| 处理时间 | |

### 业务规则

- 支持筛选：待处理 / 已处理 / 全部
- 每条预警处理后不可撤回，但可查看处理历史

## 5.3 管理员改错（清除/补录）

### 功能说明
管理员清除误扫记录或为漏扫的工人补录工序。提供两个操作入口。

### 入口1：异常处理页面
- 汇集所有待处理的断层预警
- 从预警列表一键跳转到清除或补录操作
- 适合日常巡查、批量处理

### 入口2：扎号详情页
- 在扎号详情的工序列表中，每道已完成的工序旁边有「清除」按钮
- 在扎号详情中也可以直接「补录」某道工序
- 适合已定位到某个扎号时直接操作

---

### A. 错误清除

#### 操作流程
1. 管理员找到需要清除的报工记录（从预警跳转或手动搜索扎号）
2. 点击「清除」按钮
3. 弹出确认弹窗，填写清除原因
4. 确认清除

#### 确认弹窗字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 报工信息 | 只读 | - | 展示：扎号、工序、报工人、件数、时间 |
| 清除原因 | 文本 | 是 | 如：「工人扫错工序」 |

#### 系统执行逻辑
1. 将该报工记录状态改为「已清除」
2. 扣减该工人的计件工资
3. 释放该工序（状态变回未完成）
4. 若该扎所有工序已完成（已封死），则状态变回「生产中」，QR码复活
5. 记录操作日志（操作人、时间、原因）

---

### B. 手工补录

#### 操作流程
1. 管理员选择扎号（搜索或从预警跳转）
2. 选择要补录的工序
3. 选择报工的工人
4. 填写件数（默认等于该扎件数）
5. 填写报工时间（默认当前时间，可手动修改）
6. 确认补录

#### 补录弹窗字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 扎号 | 搜索选择 | 是 | |
| 工序 | 下拉选择 | 是 | 只显示该扎未完成的工序 |
| 工人 | 下拉选择 | 是 | |
| 件数 | 数字 | 是 | 默认等于该扎件数 |
| 报工时间 | 日期时间 | 否 | 默认当前时间，可手动修改 |

#### 系统执行逻辑
1. 创建一条新的报工记录（标记为「补录」）
2. 增加该工人的计件工资
3. 标记该工序为已完成
4. 若所有工序完成，扎状态变为「已完成」，QR码失效
5. 记录操作日志

- 菜单修改后，权限配置页面实时同步

## 7.2 角色管理

### 功能说明
管理系统中的角色，每个角色关联一组权限。员工通过关联角色获得对应的系统权限。

### 页面布局
- **列表页**：角色列表 + 新增按钮
- **详情页**：角色信息 + 权限配置

### 角色列表页字段

| 字段 | 类型 | 说明 |
|------|------|------|
| 角色名称 | 文本 | 如：报工角色、组长角色、财务角色 |
| 角色说明 | 文本 | |
| 包含员工数 | 数字 | 该角色下有多少员工 |
| 操作 | 按钮 | 编辑、配置权限、删除 |

### 新增/编辑角色弹窗

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 角色名称 | 文本 | 是 | |
| 角色说明 | 文本 | 否 | |

### 业务规则
- 系统预设角色不可删除（如：超级管理员）
- 有关联员工的角色不可删除，提示「该角色下有N名员工，请先转移员工」
- 新增角色默认无任何权限，需手动配置
- 只有管理员可以操作角色管理

## 7.3 权限配置

### 功能说明
为每个角色分配可访问的功能页面和可执行的操作。菜单树从菜单管理中动态加载。

### 页面布局
在角色详情页或点击「配置权限」进入权限配置页面。

### 权限配置页面交互

页面分两个Tab展示：

**Tab1：Web端权限**
- 展示Web端菜单树（从菜单管理动态加载，只显示所属平台为「Web端」且启用状态的菜单）
- 每个节点有勾选框
- 勾选父节点时，子节点自动全选
- 取消父节点时，子节点自动全取消
- 也可单独勾选某个子节点

**Tab2：移动端权限**
- 展示移动端菜单树（从菜单管理动态加载，只显示所属平台为「移动端」且启用状态的菜单）
- 交互方式同上

### 权限粒度

| 级别 | 说明 | 示例 |
|------|------|------|
| 目录级 | 控制菜单分组的可见性 | 能否看到「基础配置」菜单 |
| 页面级 | 控制功能页面的访问权限 | 能否进入「员工列表」页面 |
| 按钮级 | 控制页面内操作按钮的显示 | 能否点击「新增」「编辑」「删除」按钮 |

### 业务规则
- 勾选「页面」权限才能访问该页面
- 按钮权限需在「页面」权限基础上单独勾选
- 目录权限控制该目录下所有子菜单的可见性
- 超级管理员拥有全部权限（Web端+移动端），不可修改
- 权限修改后实时生效（用户刷新页面后）
- Web端和移动端的菜单统一在菜单管理中配置，通过「所属平台」字段区分
- 移动端菜单一般只到页面级，不涉及按钮级权限

## 7.4 预设角色

系统预设以下角色，不可删除，可修改权限：

| 角色 | Web端权限 | 移动端权限 | 说明 |
|------|----------|-----------|------|
| 超级管理员 | 全部 | 全部 | 系统最高权限，权限不可修改 |
| 报工角色 | 无 | 员工端全部功能 | 普通员工使用 |
| 裁床角色 | 裁床管理全部 | 员工端全部功能 | 裁床师傅使用 |
| 组长角色 | 管理后台-生产看板、异常处理、计时录入 | 管理员端全部功能 | 车间组长使用 |
| 财务角色 | 财务管理全部 + 管理后台-工资管理、报表中心 | 无 | 财务人员使用 |

管理员可在预设角色基础上修改权限，也可新增自定义角色。

## 与员工档案的关联

### 员工档案字段调整

员工档案中的「角色」字段改为下拉选择角色：

| 字段 | 类型 | 说明 |
|------|------|------|
| 角色 | 下拉选择 | 从角色管理中选择，一个员工只能有一个角色 |

### 业务规则
- 员工登录后，系统根据其角色加载对应的权限
- Web端登录：根据角色加载Web端权限，控制菜单显示、页面访问和操作按钮
- 移动端登录：根据角色加载移动端权限，展示对应的功能菜单
- 同一个员工可以在Web端和移动端拥有不同的权限范围
- 修改员工角色后，下次登录生效

## 模块7总结

| 子模块 | 核心功能 |
|--------|---------|
| 菜单管理 | 动态管理Web端和移动端的目录/页面/按钮菜单，支持多级嵌套 |
| 角色管理 | 增删改查角色，查看角色下的员工 |
| 权限配置 | 从菜单管理动态加载菜单树，按平台（Web/移动）分别配置权限 |
| 预设角色 | 系统预设常用角色，不可删除，可修改权限 |

## 业务规则汇总

- 只有管理员可以操作菜单管理和角色管理
- 菜单修改后实时同步到权限配置页面
- 权限修改后用户刷新页面即可生效
- 超级管理员权限不可修改
- 有关联员工的角色不可删除
