# 模块3：裁床与开菲 - 需求文档

## 概述

裁床与开菲模块是生产的起点。本模块负责将订单计划转化为具体的裁床单（Bed），通过管理唛架比例（Marker Ratio）和拉布层数（Plies）自动计算产出成衣件数，生成并打印带有裁床码和扎号二维码的菲仔（Ticket），确保生产数据的准确性与面料色差的控制。

---

## 3.1 裁床单管理

### 功能说明
裁床单是裁剪作业的核心单据，记录每一床裁剪的详细方案。

### 页面布局
- **列表页**：裁床单列表 + 筛选栏 + 新增按钮
- **详情页**：基本信息 + 唛架配置 + 拉布记录 + **裁片组成 (齐片检查)** + 分扎预览

### 列表页字段 (略)

### 裁床单详情 - 数量口径

裁床计划和后续报工统一以**成衣件数**作为主数量。裁片片数只用于裁床核对、齐片检查和菲仔展示，不作为计件报工数量。

| 字段 | 计算方式 | 说明 |
|------|----------|------|
| 配比 | 手动录入 | 每层布料排出的成衣件数 |
| 计划成衣件数 | 层数 × 配比，允许手动修正 | 用于生成计划数和默认实际数 |
| 单件裁片数 | 款号裁剪部位BOM带出 | 如袖子2片/件、前幅1片/件 |
| 计划裁片片数 | 计划成衣件数 × 单件裁片数 | 只读展示，用于核对裁片 |
| 实际成衣件数 | 裁完后手动录入 | 用于分扎、报工和工资计算 |
| 实际裁片片数 | 实际成衣件数 × 单件裁片数 | 只读展示，用于核对裁片 |

### 裁床单详情 - 唛架配置 (略)

### 裁床单详情 - 拉布记录 (Spreading Record)

记录实际铺设的层数和面料来源：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 实际层数 (Plies) | 数字 | 是 | 如：50层 |
| 面料选择 | 下拉选择 | 是 | 从订单物料清单中选择面料 |
| 面料缸号 (Dye Lot) | 文本 | 是 | 强制录入，确保同床/同扎无色差 |
| 门幅/缩率 | 数字 | 否 | 记录实际投入的面料参数 |

### 裁床单详情 - 裁片组成 (齐片检查)

系统根据款号关联的部位自动带出，用于核对是否所有裁片都已备齐。

| 裁片部位 | 需裁数量 (单件) | 本床计划成衣数 | 本床计划裁片片数 | 已备齐 | 备注 |
|------|------|------|------|------|------|
| 前片 | 1 | 50 | 50 | 勾选 | |
| 后片 | 1 | 50 | 50 | 勾选 | |
| 袖子 | 2 | 50 | 100 | 勾选 | |

## 3.2 自动分扎与开菲 (Bundling Logic)

### 功能说明
在裁剪完成后，且**所有裁片勾选“已备齐”**后，系统根据分扎规则将实际成衣件数拆分为独立的「扎」。

### 业务规则
- **齐片约束**：未勾选齐片的裁床单禁止“开菲”。
- **缸号一致性**：同一扎内的裁片必须来自同一缸号。
- **外发标记**：若部位档案中标记了“需印花”，系统在分扎时自动生成“外发工作单”索引。


---

## 3.3 菲仔（工票）打印

### 功能说明
打印附着在裁片扎上的标签，是工人扫码报工的唯一凭证。

### 菲仔内容要素
- **核心信息**：款号、颜色、尺码、扎号、成衣件数、裁片片数、床号。
- **追溯信息**：面料缸号、订单号。
- **扫码标识**：
    - **裁床码 (Barcode)**：全床通用，裁床师傅扫码完成「裁剪」工序。
    - **扎号码 (QR Code)**：每扎唯一，车缝工人扫码报工。

### 打印样式示例
```
┌─────────────────────────────┐
│ 订单：ORD20240101001         │
│ 款号：SP-001      床号：01   │
│ 颜色：黑色        尺码：M    │
│ 扎号：1-002      件数：30   │
│ 部位：袖子       片数：60   │
│ 缸号：LOT2024A              │
│                             │
│ ┌───────┐      ┌─────────┐  │
│ │ 裁床码  │      │  扎号码  │  │
│ │(条形码) │      │ (QR码)   │  │
│ └───────┘      └─────────┘  │
└─────────────────────────────┘
```

## 3.4 裁床工序报工

### 工艺流程监控
裁床车间包含两个关键上报动作：

1. **拉布完成**：
    - 录入实际层数和缸号。
    - 系统计算出计划成衣件数和计划裁片片数。
2. **裁剪完成**：
    - 裁床师傅扫「裁床条形码」。
    - 系统自动为该床所有扎号完成「裁剪」工序。
    - 计件工资 = `该床实际成衣件数 × 裁剪单价`。

### 业务规则
- 必须先「拉布完成」才能「裁剪报工」。
- 「裁剪报工」后，扎号QR码正式激活，可进入下一道工序。

---

## 3.5 扎号状态管理

### 状态流转
- **待裁**：裁床单已创建，尚未拉布/裁剪。
- **生产中**：已裁剪报工，进入车缝环节。
- **已完成**：该扎所有工序（如车位、后整、质检）均已扫码完成。

### QR码失效与复活
- **失效**：当扎号处于「已完成」状态，或被管理员手动封存时，扫码报工无效。
- **复活**：管理员清除最后一道工序的错误记录后，扎号自动恢复为「生产中」，QR码重新生效。

## 模块总结

| 子模块 | 核心改进点 | 业务价值 |
|--------|-----------|---------|
| 裁床单管理 | 引入唛架比例与层数计算 | 消除手动计算错误，精确控制产出 |
| 色差控制 | 强制关联面料缸号 (Dye Lot) | 避免成衣出现阴阳色，提升质量 |
| 自动分扎 | 跨尺码独立分扎逻辑 | 规范裁片流转，方便车位作业 |
| 菲仔系统 | 双码设计（裁床码+扎号码） | 兼顾大批量裁床报工与精细化扎号追踪 |
